# groebner-runtimes

Сравнение времени вычисления базисов Грёбнера в **SymPy** и **GInv** на наборе тестовых систем уравнений.

Репозиторий содержит код и данные для воспроизведения вычислительных результатов эксперимента: для одного и того же набора тестовых систем запускается построение базиса Грёбнера двумя способами — через классическую реализацию в **SymPy** и через инволютивный подход в **GInv** — после чего результаты сохраняются в JSON/CSV и анализируются в Jupyter Notebook.

## Структура репозитория

- **`main.py`** — основной скрипт запуска экспериментов.
- **`config.py`** — конфигурационный файл, который включает список тестов, группы по сложности, порядок мономов, директории и конфигурация запуска.
- **`test_runners.py`** — реализации вычисления базиса Грёбнера:
  - `SympyRunner` — вычисление через `sympy.groebner(...)` с использованием классического полиномиального деления;
  - `GinvRunner` — вычисление GInv с использованием инволютивного деления.
- **`timeout_utils.py`** — вспомогательные функции для запуска тестов с ограничением по времени.
- **`utils.py`** — полезные функции: загрузка входных данных и сохранение результатов.
- **`json-benchmarks/`** — входные тестовые системы в JSON-формате.
- **`results/`** — результаты отдельных прогонов по тестам.
- **`summary_table_<...>.csv`** — сводные таблицы результатов эксперимента.
- **`stat_analysis.ipynb`** — файл для статистического анализа и построения графиков.
- **`figures/`** — готовые графики, полученные по итогам анализа.

## Возможности

Код позволяет воспроизвести:

- время вычисления базиса Грёбнера в **SymPy** и **GInv** (а также позволяет легко добавить новый метод для вычисления);
- размер полученного базиса;
- при необходимости — замерить метрики памяти;
- итоговые таблицы по всем тестам;
- графики и статистический анализ результатов, выявление закономерности, расчет метрик.

## Быстрый старт

### 1. Запуск всех тестов

```bash
python main.py
```

Скрипт:

- загружает тестовые системы из `json-benchmarks/`;
- последовательно запускает `ginv` и `sympy`;
- сохраняет отдельные результаты в `results/`;
- собирает общую таблицу результатов в CSV.

По умолчанию в `main.py` включены:

- методы: `ginv`, `sympy`;
- порядок: `deglex`;
- таймаут: `3600` секунд;
- сохранение общей CSV-таблицы;
- режим без измерения памяти (`MEASURE_MEMORY = False`).


### 2. Построение графиков и анализ

После вычислений открыть ноутбук:

```bash
jupyter notebook
```

и выполнить `stat_analysis.ipynb`.

Ноутбук читает сводную таблицу, подготавливает данные и строит графики, которые сохраняются в `figures/`.

## Формат входных данных

Каждый тест в `json-benchmarks/` задаётся JSON-файлом и содержит:

- имя/идентификатор теста;
- список переменных;
- систему полиномиальных уравнений;
- размерность системы;
- при наличии — описание.

Один и тот же тест используется и для `SymPy`, и для `GInv`.

## Формат результатов

Для каждого теста сохраняется отдельный JSON-файл вида:

- `<test>_<method>_<order>.json`

В результатах фиксируются:

- `test` — имя теста;
- `method` — метод (`ginv` или `sympy`);
- `order` — порядок мономов;
- `time` — время вычисления;
- `dimension` — размерность задачи;
- `num_vars` — число переменных;
- `basis_size` — размер базиса;
- `status` — статус выполнения (`ok`, `timeout`, `error`);
- при запуске с измерением памяти — `avr_memory`, `max_memory`, `mem_per_sec`.

## Конфигурация

Основные параметры запуска задаются в `main.py` и `config.py`.

Наиболее важные:

- `METHODS` — какие методы запускать;
- `CATEGORIES` — какие тесты включить;
- `ORDERS` — порядок мономов;
- `TIMEOUT` — ограничение по времени на один тест;
- `MEASURE_MEMORY` — включить/выключить измерение памяти.

В `config.py` тесты уже разбиты на группы:

- `VERY_QUICK`
- `QUICK`
- `MEDIUM`
- `LONG`
- `TOO_LONG`
- `ALL`

Это позволяет запускать либо весь набор, либо отдельные подмножества.

## Что уже есть в репозитории

В репозитории уже присутствуют:

- набор входных бенчмарков;
- результаты отдельных прогонов;
- сводные таблицы;
- готовые графики.

То есть репозиторий можно использовать в двух режимах:

- как **архив уже полученных результатов**;
- как **воспроизводимый вычислительный проект**, который можно заново запустить на чистой машине.

## Замечания по воспроизводимости

Абсолютные времена могут незначительно отличаться на другой машине, но качественная картина сравнения должна сохраняться при тех же:

- входных данных;
- порядке мономов;
- версиях библиотек;
- параметрах таймаута.
